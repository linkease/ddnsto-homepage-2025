# M1–M7 开发与验收计划（历史）

2026-11 新原型改造请执行 [本轮 M1–M6](refresh-2026/PLAN.md)，不要沿用本文阶段编号推进。本文保留原实现与验收依据。

## 执行规则（用户明确要求）

按 M1 → M7 顺序执行。每个里程碑开始前，在对话中输出本阶段任务树和验收标准，再实现和自检。初次自检不计优化次数；发现未达标项后，最多进行 3 轮“修复 → 复测”，每轮记录问题、改动和结果。3 轮后仍未达标，报告未达标并停下，不降低标准、不转入下一里程碑。

达标状态为“已通过自检，等待用户确认”。只有用户明确同意进入下一阶段才继续；对上一阶段提出修改不等于批准进入下一阶段。换会话读取 PROGRESS 和对应里程碑报告，保留轮次及确认状态。通过构建或参考稿测试均不等于业务功能已实现。

本计划中的“业务正常”指官网展示、场景模拟、安装信息和跳转流程正常。真实控制台登录、支付扣款、真实设备远控属于外部产品，不能用前端模拟宣称其端到端业务已验证。检查官方入口和到达页面，涉及账号/支付的测试须具备相应条件。

公共规则：修改限新项目、参考快照只读、原 6002 服务不动；每阶段回归已有功能；类型/格式/静态构建检查通过；实际渲染验证记录控制台与资源错误、截图和操作结果。

## M1：设计基准与工程验收规则

任务树：

- 固定 M1–M7 任务及用户确认节点，接入开发规范。
- 校验设计快照，建立纯本地参考服务和可重复采集命令。
- 采集 360/390/768/1024/1440px 的 minimal 主题、正文/结构/实际样式。
- 保存桌面/手机初始视口及四类场景截图，检查设备选择、FAQ、手机菜单。
- 增加独立性、参考哈希、产物边界、预览禁索引测试；回归现有框架。

验收：

- 快照文件与 manifest 全量一致；采集记录包含 5 个宽度、主题、浏览器版本、错误/失败请求及横向溢出结果。
- 390/1440px 各 4 个场景的选择/重置状态、设备选择、FAQ 空结果/清空/展开，以及手机菜单开关均有结果。
- 截图及实际样式记录可供 M2 对照；参考稿自身问题有编号、影响与归属，不能冒充已修复。
- npm run validate 和 npm run test:e2e 全部通过，默认预览 noindex，发布产物不依赖父目录和参考服务。
- 不实现 M2 UI，保留框架占位页；形成 M1 报告并等待确认。

## M2：设计变量、导航、首屏、需求导航

任务树：

- 从 M1 实测样式提取 minimal 设计变量和响应式规则。
- 实现品牌页头、桌面导航、手机菜单、控制台入口。
- 实现首屏文案、关键词与对应入口、场景动画和减少动效状态。
- 实现需求导航、滚动高亮与锚点定位；为未完成区域保留明确占位，不伪装已完成。

验收：

- 5 个宽度无横向溢出/文本或按钮遮挡；390/1440px 固定状态截图逐区块比较。
- 主要容器/标题/按钮相对参考坐标与尺寸偏差 <=4 CSS px，允许字体抗锯齿差异；有意改动先记录并由用户确认。
- 手机菜单可打开、Escape/关闭按钮关闭、焦点返回；点击导航到对应目标，目标标题不被固定导航遮住。
- 关键词与 CTA 指向正确场景/设备入口；无脚本时正文及关键链接可读。
- 减少动效模式无自动轮播；后台/离屏停止不必要播放；无相关运行时错误。

## M3：四类场景交互演示

任务树：

- 建立场景数据、状态及键盘标签切换。
- 实现应用发现、选择服务、添加域名、结果演示。
- 实现 TCP 桌面配置/进入模拟桌面/断开与返回。
- 实现文件管理配置/进入目录/文件预览和示例下载。
- 实现设备启用/生成链接/模拟控制台，统一重置与 CTA。

验收：

- 四类场景各至少 1 条完整成功路径；有输入校验的流程至少 1 条失败及恢复路径。
- 每个场景在中间步骤和完成步骤均可重置到初始状态；快速切换不会遗留计时器结果到另一场景。
- 键盘方向键、Home/End、Tab 焦点与 aria-selected 同步；手机操作正常。
- 显式模拟数据；无真实扫描、远控或提交请求；下载只生成示例文件。
- 交互后不会被自动轮播打断；390/1440px 截图对照及已完成模块回归通过。

## M4：设备选择与安装指南

任务树：

- 逐项核实参考列出的平台、型号/固件分支及官方文档。
- 建立有类型的设备和安装内容源，记录来源/核实日期。
- 实现平台分组、指南步骤、截图、命令、选项和场景意图衔接。
- 实现复制成功、权限拒绝/不支持时的手动复制回退。

验收：

- 每个公开平台和固件分支都有数据驱动检查；选择后展示对应标题、步骤、官方链接。
- 空/未知参数有清晰回退；切换设备不残留上一平台的命令/图片。
- 复制成功与拒绝两条路径均测试；命令只展示/复制，不自动执行。
- 所有指南图片本地加载，无断图；长命令在手机容器内滚动，不撑宽页面。
- 关键安装说明存在初始 HTML 或可抓取独立页面；未核实平台信息不作为正式承诺发布。

## M5：套餐、FAQ、客服与页脚

任务树：

- 核实价格、套餐单位、权益、单设备规则和 TCP 活动条件。
- 实现套餐卡片与官方购买入口，不构建支付服务。
- 实现 FAQ 分类/搜索/计数/展开/查看更多及来源。
- 实现客服角色、二维码、帮助/活动弹层和页脚。

验收：

- 展示值与已核实内容源一致；价格差异和活动有效期问题已解决，否则该项不达标。
- 购买/控制台/教程 href 与核实地址一致；外部入口 HTTP/浏览器可达性有记录，不进行真实付费。
- FAQ 测试分类、命中、无结果、清空恢复、查看更多和展开行为；搜索覆盖所有数据。
- 弹层支持关闭、Escape、焦点返回，手机不遮挡主要 CTA；二维码来源正确且可读。
- 公司与备案信息来源明确，所有已实现模块回归通过。

## M6：SEO 与可抓取内容页

任务树：

- 明确正式域名与路由，建立真实场景/设备内容页及内部链接。
- 完成每页元信息、canonical、分享图、结构化数据与语义标题。
- 完成预览/生产索引策略、sitemap、404、旧 URL 映射方案。
- 检查禁用 JavaScript 时的内容与所有本地链接/图片。

验收：

- 每个正式路由返回可读正文、唯一主标题及匹配的元信息；重要内容不依赖点击生成。
- canonical、sitemap 和结构化数据使用同一已确认域名；结构化事实与可见页面一致。
- sitemap 不含占位/404/禁止索引页面；预览仍禁索引，生产已验收路由可索引。
- 本地链接无死链；不存在重复的占位内容页；正确 404 状态和部署跳转规则有测试或宿主验收记录。
- 不以搜索排名作为阶段通过条件；正式域名未确认时不能宣称生产 SEO 验收完成。

## M7：全站回归与发布准备

任务树：

- 全站业务路径、异常恢复、无障碍和视觉回归。
- Chromium/Firefox/WebKit 自动化；真实 Safari/iOS/Android/微信按实际条件验证并分别记录。
- 进行资源、实验室性能与依赖风险检查，准备真实用户指标监测方案。
- 准备静态部署、缓存、404/重定向、上线检查和回滚说明。
- 汇总验收、遗留问题与发布建议，等待用户后续发布指令。

验收：

- 用户从首页找到场景 → 选择设备 → 阅读安装 → 进入官方入口，以及套餐/FAQ/客服路径全部通过；异常分支可恢复。
- 无阻断交互、关键错链、未核实商业承诺或隐蔽资源依赖；所有影响业务的严重缺陷已修复。
- 实验室测试记录浏览器、设备模拟、网络、次数和结果；至少 3 次取中位数，LCP <=2.5s、CLS <=0.1 为目标；INP 用上线后真实数据验证，不以 Lighthouse 分数代替。
- 依赖告警逐项分析可达性和部署影响，不能把未修复问题写作“全部安全”。真实设备缺席不得写成已通过，需用户接受测试范围限制后再建议发布。
- 产物可独立部署，回滚步骤明确，尚未执行生产切换。M7 通过不自动授权发布。
