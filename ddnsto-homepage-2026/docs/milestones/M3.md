## M3-001：已解决（下述为修复前现象）

首屏轮播到后续画面后启用 `prefers-reduced-motion: reduce`，动画停止，但没有回到约定的电脑静态首帧。最终全量用例在桌面与手机均观察到 `data-running=false`、`data-scene=device`，期待值为 `computer`。

这不是只靠失败断言推测：另用新的 Chromium 页面、不安装模拟时钟，等待轮播到 software 后启用减少动效，300ms 后读取到 `reduced=true`、`running=false`、`scene=software`、关键词“软件”。因此不能把它直接归为测试假失败。该记录用于保留修复前证据，专项修复结果见下文。

相关位置：src/features/hero/motion.ts 的 sync/onReduced；tests/e2e/m2-navigation.spec.ts 的动画同步用例。第 3 轮增加模拟时钟推进未解决。没有删除断言、跳过用例或降低标准。

## 实现边界与参考差异

- `Scenarios.astro` 提供语义化初始 HTML；`state.ts` 定义场景数据和状态；`views.ts` 是纯模板函数；`controller.ts` 独立管理任务、事件、焦点与状态；`scenarios.css` 限定模块样式。没有整包加载参考逻辑、iframe、旧项目文件或新的依赖。
- 模板、SVG 和模块样式提取自本地 reference/design/v2/assets/scenario-tabs.js、scenario-tabs.css 与 ui-themes.css；品牌图使用已复制的 public/images/brand/ddnsto-logo.png。参考快照 75 个文件哈希检查通过，原 6002 服务未操作。
- 为区分浏览器桌面与本地 TCP 客户端，TCP 初始说明改为“此处模拟浏览器桌面；TCP 转发需配合本地 RDP / VNC 客户端。”390px 多一行约 25.2px；套餐说明不把未核实权益写成承诺。该变化已在实现前说明，属于内容澄清而非完全逐字复刻。
- 文件密码选项明确为“仅本次演示记住”，只存在内存状态，没有保存用户凭证。诊断说明明确未发起网络检测；复制失败提供可手动复制的地址。
- 场景不自动轮换，不因离开视口自动丢弃已完成步骤；进行中的扫描/链接生成在切换、重置或页面隐藏时取消。它与原稿自动轮换/再次进入重置的策略不同，目的是保持用户操作连续。
- TCP 的套餐 CTA 指向现有 #pricing 占位区域，避免 #advanced-plan 尚未实现造成死锚点；M5 实现套餐后再核实具体入口。
- 原设计预览条、主题选择器及 M5 浮层不属于本次实现。设备安装、套餐等后续区域仍明确占位。

## 用户授权后的专项修复

用户在原三轮停止后明确回复“继续”。本次追加 2 轮修复（动效状态、截图复核发现的容器间距），不重置或隐藏原三轮记录，不扩展到 M4。

复现与定位：

- 原模拟时钟用例桌面/手机均重现失败；临时真实时钟脚本 `node /tmp/m3-reduced-check.mjs` 也以 computer 预期、software 实际失败。
- 仅在浏览器响应中插入诊断，确认媒体监听已注册、没有提前移除、没有页面异常；手动派发同一回调可回到首帧。
- 当前 Chromium 环境的差分实验：原逐帧读取 MediaQueryList.matches 时该对象未派发变更回调，而新建的独立查询对象能收到事件；单独移除帧内读取，或改为事件维护本地状态，均恢复首帧。此处描述实测触发条件，不推断所有浏览器都存在相同行为。

修改：

- motion.ts 初始化读取偏好，随后用 change 事件的 matches 更新本地 reducedMotion，动画循环只读本地状态。
- sync 统一处理暂停、首帧、关键词、链接和控件状态，避免“停止动画”与“重置画面”分散在不同触发路径。
- 浏览器缓存恢复时重新读取当前偏好后同步状态，保持原有离屏/后台/手动暂停逻辑。
- 最终截图复核发现外层 .scenarios-section 的 scoped 选择器误把容器自身写成后代，导致 88px 桌面/56px 手机上下间距未生效。修正两处选择器，并将 #scenarios .section-head 加入五宽度几何回归，不仅检查面板内部。
- 新增 hero-reduced-motion.spec.ts：不安装模拟时钟，实际轮播到 software 后开启减少动效，验证 computer/phase 0/电脑/#tcp-scenario 及可见画面，再关闭减少动效验证恢复播放。原回归断言保留。
