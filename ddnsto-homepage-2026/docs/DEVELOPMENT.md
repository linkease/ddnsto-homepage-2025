# DDNSTO 2026 开发规范

本文是后续 AI 会话的开发约束入口。开始任何开发前先完整阅读本文，再阅读 ARCHITECTURE.md 与 PROGRESS.md；说明本次涉及的模块及完成标准后执行。用户最新明确要求优先于本文，发生冲突时同步更新记录。

## 1. 项目边界

项目根是 ddnsto-homepage-2026。所有代码、依赖、资源、构建及测试配置必须在本根目录内自包含。可以整体移到任意空目录运行 npm ci 和构建。

不得 import 父项目文件，不得依赖父级 node_modules、配置、环境文件或符号链接，不得使用 file:../ 依赖。项目内模块间正常的相对 import 不受限制。修改限定在新项目内；保留旧官网以及原 6002 服务。参考文件只读，不运行 build-v2.cjs。

## 2. 开始任务的顺序

执行里程碑任务时，先读取 PROGRESS 中的当前确认状态。2026-11 新原型改造使用 [本轮 M1–M6 计划](refresh-2026/PLAN.md)；[原 M1–M7 计划](MILESTONES.md) 仅作为历史验收依据。每个里程碑必须先输出任务树与验收标准；实现后自检，未达标最多优化 3 轮；达标后停止，等待用户明确确认进入下一阶段。此流程来自用户要求，换会话仍适用。

1. 检查 cwd 和 git diff，识别用户已有改动；阅读本规范、架构及进度。
2. 确定目标模块、参考画面/交互状态、待核实内容。本轮先查 refresh-2026/M1.md 登记的新原型与采集基准；旧 reference/design/v2 仅用于原功能追溯，不把 2025 项目当需求来源。
3. 列出本次完成标准：例如状态切换、手机布局、键盘操作、HTML 可见内容。需要外部信息时标注依据。
4. 实现最小完整流程，运行对应检查，最后更新 PROGRESS.md。报告已验证与未验证项，不能用“构建成功”代替视觉或交互验收。

## 3. 参考优先级与资源

本轮视觉基线是用户提供的 ddnsto-original-prototype 的 /original-preview/?v=tcp-plan 实际效果，来源、哈希、采集条件与冲突见 [本轮 M1](refresh-2026/M1.md)。原型只读，不在原目录构建或更新服务。用户已确认以新稿及源码确定展示结构，价格按新稿；采用中文、扫码演示和 AI 提示词复制，详见本轮计划的已确认决策。保留业务能力，清理被替换的旧 UI 专用实现；新增不确定事项仍先确认。

2026-11-26 人工验收追加要求：删除首页“交互体验”“传统手动配置流程参考”“查看全部问题与搜索”及展开内容、专用代码和资源。此明确授权替代上述三个旧模块的保留要求；仍保留新稿人群区、七条 FAQ、安装/套餐/客服与独立指南路由。历史验收记录仅用于追溯，不据此恢复已删除模块。

旧 reference/design/v2/index.html 的 minimal 效果与 reference/manifest.json 保留作历史依据，不再作为本轮新视觉目标；参考资料不进入公开构建，也不是生产运行依赖。

正式 UI 将已确认的素材复制到 public/images 或 src/assets，并在 PROGRESS 的资源记录中登记原路径与用途。禁止运行时请求原设计服务器或引用原工程绝对路径。外部官方控制台/文档链接是业务入口，不属于资源依赖。

生产代码重写参考中直接改 DOM 的逻辑，不能嵌入原页面 iframe 或整包加载 original-modules。提取本轮参考实际生效的设计变量，不叠加全部历史 CSS 补丁。图片保留尺寸与 alt；首屏关键图片优先，其他图片按需加载。

## 4. 工程与内容规则

按 ARCHITECTURE 的目录职责组织代码。TypeScript strict；数据有类型，组件以 PascalCase，工具和数据以 camelCase。页面文本、FAQ、设备、套餐内容从统一内容源读取，不能在动画和正文各维护一份业务事实。

默认 Astro 输出静态正文；局部复杂交互才使用 React 岛。首屏必要交互按需 client:load，非首屏优先 client:visible。可索引正文不能使用 client:only 或等待 useEffect 才生成。简单原生 details/button/link 优先，避免不必要的全局状态。

样式按模块隔离，跨模块视觉值放 styles/tokens.css。减少动效需要真实静态/简化状态，不能仅设置一个无关媒体查询。动画在离屏、后台暂停，清理监听器与定时器；避免高频尺寸/布局变化。

输入、按钮、标签页、弹层具备语义、焦点、键盘和触摸行为；弹层关闭后焦点回到触发点。对原生 popover/dialog 按支持矩阵提供回退。安装命令只能展示/复制，不自动执行。演示使用模拟数据且明确标识。

参考的 content.json 等历史文件可能与最新页面冲突。价格、流量、套餐权益、系统支持、联系方式和备案必须记录官方来源及核实日期；冲突列入 PROGRESS，不能猜测或发布虚构数据。

## 5. 搜索与发布边界

开发和预览默认 noindex，并用 robots 禁止抓取。正式部署必须显式配置 SITE_ENV=production 和确认后的 HTTPS SITE_URL；占位页与 404 保持 noindex。robots 不是访问控制，若预览已暴露公网，应再配置访问限制。

正式正文、FAQ 与产品事实直接出现在 HTML；有真实内部链接。发布时实现独立 title/description/canonical/分享元信息，以及与页面一致的结构化数据；sitemap 仅收录 config/publishing.mjs 中登记的可索引正式路由；列表为空时不生成 sitemap，robots 保持禁止抓取。删除占位页的 noindex 前先验收内容并调整对应测试。

上线前核对主域名、旧 URL 跳转、真实 404 HTTP 状态、CDN 缓存及爬虫规则。技术验收可以证明可抓取，不能承诺所有引擎收录或排名第一。llms.txt 不属于排名保证措施。

## 6. 验证与完成标准

通用变更运行 npm run validate；影响渲染/交互还要运行 npm run test:e2e 并按改动补充有意义的用户流程测试。开发依赖由本项目安装，提交 lockfile，不提交 node_modules/dist/运行密钥。

UI 验证至少比较 390px 手机和 1440px 桌面，并检查 360、768、1024px 布局边界。最终发布覆盖 Chrome/Edge/Firefox/Safari，iOS Safari、Android Chrome、微信浏览器按实际入口验证；无法测试的环境明确列出，不能推断通过。

视觉对照固定主题、视口、字体和动画状态，记录关键区块截图差异。检查无横向溢出、遮挡、断图、运行时异常和失败请求，以及导航、场景重置、设备选择/复制、FAQ、客服的完整行为。

性能目标：真实用户第 75 百分位 LCP <=2.5s、INP <=200ms、CLS <=0.1；上线前实验室指标作参考，上线后验证真实数据。任何动效降级都记录与参考的差异和原因。

完工后在 PROGRESS 更新范围、验证结果、待解决问题、资源来源与下一步。发生架构调整时同步更新 ARCHITECTURE。仅完成框架时明确标注业务/UI 尚未实现。

## 7. 新会话使用方式

可给 AI 以下指令：

> @ddnsto-homepage-2026/docs/DEVELOPMENT.md 请先完整阅读并遵循此开发规范，再阅读同目录的 ARCHITECTURE.md 和 PROGRESS.md。仅在 ddnsto-homepage-2026 独立项目内继续开发。先说明当前状态和本次验收标准，完成后运行相关检查并更新进度。

AGENTS.md 作为工具支持时的自动入口；即使工具没有自动加载 AGENTS，也要用上述规范显式引导。

2026-11-26 用户确认正式入口 https://web.ddnsto.com/（www 跳转至此），并授权使用正式后端联调扫码登录与设备令牌获取。按 docs/install-auth/PLAN.md 分阶段执行；这替代此前“扫码只能演示”的范围限制，但不授权执行安装命令、创建业务设备、支付或生产部署。参考 console-2026 仍只读。不得将真实扫码凭据、账号 token 或 Cookie 写入日志、测试快照、进度文档或 URL。
